# 内容研究与实验

> v0.1 通用草案：已补充一轮 [GitHub 公开方法研究](references.md)，可以手工试用；流程假设仍待真实反馈检验，不代表方案已定型。

以自己的观察、思考和实践为起点，把发布当作一次小型产品实验：提出假设，获得反馈，验证，再复盘。热点与别人的经验帮助理解读者和表达方式，不能代替自己的判断。

## 从哪里开始

先记录自己的观察、观点、实践或作品：哪些值得保留，能帮助谁，依据是什么？每次行动后都可以考虑留下一点有用的认识，但不要求每次都产出内容。

再参考市场问题、热点和别人的做法，寻找与真实思考相合的切入点。补充观察可以启发新问题，选题仍需回到自己的判断与证据。

自己的观察与思考 → 内容假设 → 参考研究与平台适配 → 确认后发布 → 反馈与验证 → 复盘 → 下一次实验。

热点只是选题来源之一。一个想法是否值得发布，要看它能否说清楚、是否有真实依据、对读者是否有帮助，不能靠“任何观点都能获得流量”的假设。

## 第一轮怎么做

1. 在已核对访问权限的工作区记录一个自己的想法及证据；需要参考外部内容时，再复制 [观察卡](templates/observation.md)。
2. 用 [研究简报](templates/daily-brief.md) 整理零到三个机会。没有足够证据时可以是零个。
3. 选一个机会，填写 [发布实验](templates/experiment.md)：先定目标、主要指标和比较方法，再写稿。
4. 取得具体稿件与发布位置的确认后再发布；按真实发布时间安排快照。
5. 复盘后填写 [学习卡](templates/learning.md)，决定保留、修改复测、暂停或继续补证据。

小红书、抖音先按各自形式研究；公众号可以作为第三个平台研究长文表达与读者反馈。新增平台不代表已连接账号或启用自动化，指标与基线始终分开。

日常步骤见 [SOP](SOP.md)，数据口径见 [指标说明](METRICS.md)，经审阅可公开的结论放入 [经验目录](learnings/README.md)。

## 建议节奏与当前状态

- 建议每天研究一轮、最多给出三个机会，每周回看实验与经验。
- 首轮可从 AI 产品与工作流、个人学习实践中选题；这是可调整的研究建议。
- 日常研究、发布频率和两周试验均需结合时间与数据来源确定，不为保持频率牺牲判断。
- 每份内容先检查保密、隐私、事实依据、声誉风险与制作成本，再决定当次发布、每周汇总或暂存；选定发布时仍需具体确认。
- **当前版本只有方法与空白模板，可以手工运行。未启用定时研究、账号数据同步或自动发布，也没有已验证的发布规律。**
- 24 小时 / 72 小时 / 7 日是建议的观察窗口，只有实际发布后才适用。

## 公开与私下记录的边界

这个仓库是公开的，只存方法、空白模板和经过单独审阅的聚合经验。

实际观察、草稿、个人观点、本人作品指标和实验记录，请在确认过访问权限的工作区填写。使用 Notion 等工具时先核对页面、上级页面及工作区的分享范围，不能仅因“放在 Notion”就视为私密。两个集合即可起步：内容观察、发布实验；学习结论先写在实验复盘里。

以下内容不提交到本仓库：账号信息、本人单条作品指标、未发布稿件、私人观点、后台截图、评论者身份、第三方全文或完整脚本、凭据以及私密工作区链接。分支、PR、Issue、提交消息、日志和产物也都要检查，不能只依赖忽略文件。

公开经验必须去标识、避免反推出个人或单条作品，并再次确认可公开范围。研究和写稿的授权不等于社交发布或公开真实数据的授权。

## 数据来源

1. 本人作品指标优先用官方创作者后台，或本人提供的官方导出 / 截图；没有可用读取路径时手工录入。
2. 公开内容只通过允许访问的页面、搜索结果或明确授权的读取方式观察。记录实际覆盖，不称为平台全量或实时热榜。
3. 第三方工具只作为待评估选项。[蝉妈妈开放平台](https://www.chanmama.com/open-platform/) 可进一步核对接口，但所需权限、价格、具体可用数据和持续访问方式尚未确认，初版不依赖它。
4. 不设计千瓜云端自动访问、抓取或绕行限制。其他工具的旧功能介绍也不能当作当前已验证能力。
5. 不安装爬虫、不配置凭据，不开通付费服务，也不把原始账号数据放进公开自动化日志。将来接入前另行核对条款、权限与授权。
